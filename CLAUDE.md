## When to use which skill

Do not load every skill at once: they cost context and several impose conflicting aesthetics (brutalist, minimalist, soft, taste). Pick by task.

- **New feature or behavior change:** `superpowers:brainstorming` first, then `superpowers:writing-plans`.
- **New or redesigned UI:** `impeccable`, then `21st-ui-build`. Use `21st-ui-explore` first if the direction is undecided.
- **UI review or audit:** `21st-ui-review`; `break-ui` for worst-case data (long names, empty lists, 1,000-row menus).
- **Motion:** `animate`; `improve-animations` to audit existing motion.
- **Bug or failing test:** `superpowers:systematic-debugging`.
- **Implementing a feature or fix:** `superpowers:test-driven-development`.
- **Before saying work is done:** `superpowers:verification-before-completion`.
- **Reviewing a diff:** `code-review`.
- **Mapping or questioning the codebase:** `graphify` (`/graphify .` to build, then `graphify query "<question>"`). Needs the CLI: `uv tool install graphifyy`. Output goes to `graphify-out/` (gitignored).

When two design skills disagree, follow this project's existing design system and tokens over either skill.
