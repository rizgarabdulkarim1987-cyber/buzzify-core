# Performance baseline 2026-10-16: customer menu

Lighthouse 13.5.0, default mobile profile (simulated slow 4G, 4x CPU slowdown), production builds served
locally with `next start`. Each figure is the median of five runs; the two builds were measured alternately
so machine load affects both equally.

- **main**: `c61d99d` (before this change)
- **this change**: the three `perf` commits on top of it

## Goals

| Goal | main | This change | Verdict |
|---|---|---|---|
| LCP under 2.5 s (`/atelier/en`) | 3.61 s | 2.51 s (runs 2.49 to 2.58 s) | **Not met.** Within 0.01 s of the line: 2 of 5 runs were under 2.5 s, the median is not. |
| LCP under 2.5 s (`/atelier/en?stage=off`) | 3.61 s | 2.51 s (runs 2.50 to 2.51 s) | **Not met**, by about 10 ms in every run. |
| Initial script about 120 KB | 217 KB | 166 KB | **Not met.** The framework alone is about 139 KB (see below). |

"Initial script" counts the scripts requested before the page's largest paint, which is what a visitor waits
for. Scripts fetched afterwards (the product sheet, warmed 1.5 s after load, and the 3D stage) are listed
separately. `npm run perf` now reports both.

## What changed

1. **Fonts: 172 KB to 40 KB on English pages, 190 KB to 63 KB on Arabic and Sorani ones.** `next/font`
   preloaded every face the route could reach, so the English page fetched the 94 KB Arabic face and Arabic
   pages fetched both Latin faces. Nothing is preloaded now; each page downloads the faces its language
   uses. All text is regular weight, so the faces are single 400 files, and Bodoni Moda is bundled with the
   weight pinned and its optical-size axis kept (`src/app/fonts/README.md`).
2. **Initial script: 217 KB to 166 KB.** `motion/react` builds its full component at module scope, so any
   import from it put the whole animation library (about 45 KB) in the menu's first download. The menu
   moves with CSS, the Web Animations API and a scroll listener; the library loads with the product sheet.
   An ESLint rule keeps it there.
3. **HTML: 16.4 KB to 13.5 KB.** Every product carried search text in all three languages. The page now
   carries its own language, which brings the document inside one TCP initial window; the other languages
   load from `/api/[tenant]/search-index` when the search box is first used.

## What is left, and why the goals are still missed

- **Framework floor.** Of the 166 KB of initial script, about 139 KB is React DOM, the Next.js client and
  router, and the Turbopack runtime; the app's own code is about 27 KB. A 120 KB budget cannot be met on
  this stack while the menu hydrates on the client.
- **What sets LCP in the simulation.** The largest paint is the hero. Lighthouse's model makes it wait for
  everything requested before it, so the time is mostly bytes over a 1.6 Mbit/s link: about 166 KB of script,
  40 KB of fonts, 9 KB of CSS and the HTML. An experiment with no web fonts at all measured 2.51 s against
  2.92 s with them at the time, so the two Latin faces are now the largest single cost after the framework.
  Getting clearly below 2.5 s means fewer font bytes (for example the system font for body text, about
  13 KB) or less script; both are product decisions, not done here.
- **FCP rose from 0.91 s to 1.21 s in the simulation.** Fonts are no longer preloaded, so the model starts
  them after the stylesheet. Preloading would bring FCP back, but Next attaches preloads per route rather
  than per locale, so it would again send every visitor the other script's fonts.
- **TBT on `/atelier/en` stays high** (3.7 s) because headless Chrome initialises the 3D stage with software
  WebGL after load. It is unrelated to this change and not representative of a phone GPU.
- With applied DevTools throttling instead of the simulation, an earlier build of this change measured LCP
  at 2.17 s; the simulated figure is the one the goal refers to.

## Reproduce

```bash
npm run build
npm run start
CHROME_PATH="C:/Program Files/Google/Chrome/Application/chrome.exe" npm run perf -- http://127.0.0.1:3100/atelier/en menu
```

A single run can fall either side of 2.5 s; compare medians. Results vary by machine and by what else the
machine is doing (another build or a WebGL test run in parallel moves TBT by seconds).
