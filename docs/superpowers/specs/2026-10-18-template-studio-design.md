## 1. Intent

Buzzify runs about 1,000 menus for restaurants, cafés, bakeries and ice cream shops from one Studio. Today every menu
has the same layout and only its colours, fonts and rail change. The brief asks for 30 presets that differ in
composition, navigation, typography, product presentation and motion, each with a static, a motion and a real 3D
background mode, chosen and customized per business in the Studio without touching menu content or URLs.

What a guest must get, whatever the preset: categories, products and prices on the first screen, no intros, readable
text over a quiet background, fast on an ordinary phone, three languages with correct right-to-left layout.

## 3. Decisions

| Decision | Choice | Why |
|---|---|---|
| Stack | Existing Next.js 16, React 19, Prisma 7, PostgreSQL, Tailwind 4, three.js 0.186 with React Three Fiber 9 | Brief: adapt to the existing stack |
| Scroll scrubbing | A small rAF scroll-progress signal, not GSAP | Claude's call. Progress is a pure input to each scene, so it reverses for free; GSAP would add about 70 KB to a menu already near its script budget |
| Where presets live | Code (`src/lib/templates`), versioned per preset | Claude's call. Presets come with components; data alone cannot express a layout |
| Template defaults and business overrides | `BrandConfig.templateId` plus `BrandConfig.design` (overrides only). Resolved at publish into the snapshot | Brief 7: keep them separate, version published configs. A later change to a preset's defaults reaches a menu only for fields it never overrode, and only when it is next published |
| Classic | A menu without a template keeps today's layout exactly; its snapshot hash does not change | Brief: preserve existing menus |
| Custom templates | `DesignTemplate` rows: a base preset plus overrides, owned by a restaurant or shared (null restaurant, Super Admin only) | Brief 7: duplicate and save as custom |
| Featured items | Stored by product slug, not id | Restore and duplicate give rows new ids; slugs survive |

| Ordering | `none` (menu only: no cart, no quick add, no cart page) or `list` (today's cart and order review, which never claims an order was sent) | Brief 10. Real submission is stage 4; there is no order flow to integrate with yet |

| One canvas | The background scene is the menu's only WebGL canvas; it pauses while a product's own 3D stage is open in the detail | Brief 13 |
| Thumbnails | Screenshots of the real renderer with demo content, generated by a script and committed | Brief 7: accurate thumbnails |
| Demo content | New demo restaurants, named "(Demo)", seeded like the existing three; real menus are never touched | Brief 15 |

## 4. Model

### 4.1 A preset

`TemplatePreset` (`src/lib/templates/types.ts`): id, number (1 to 30), name, business (`restaurant`, `cafe`, `bakery`,
`icecream`), style tags (`light`, `dark`, `minimal`, `cinematic`, `playful`), theme, version, palette, at least three
curated alternative palettes, font pair and type settings, layout (hero, navigation, card, detail, option style, image
ratio, density, corners, shadow, section heading style), and scene settings (scene id, default mode, intensity, speed,
ambient, tap, scroll).

The palette is the existing eight colours plus `card`, `button` and `onButton`. Rules: text and muted text on
background, surface and card must reach 4.5:1 (blocking); text on the button must reach 3:1 (blocking) and should reach
4.5:1 (warning); accent pairs warn below 3:1. A test fails if any preset or curated palette has a blocking problem.

### 4.2 Overrides and the resolved design

`DesignOverrides` (stored): palette id and manual colour edits, font pair and scale, layout fields, scene fields
(mode, intensity, speed, ambient, tap, scroll, brightness, blur, opacity, overlay), featured slugs and title, a promotion
(title, text and terms per language), which business details to show, ordering mode.

`MenuDesign` (in the snapshot, on `BrandView.design`): the resolved values, the business details copied from the
restaurant, `poweredBy`, and `source` (`templateId`, `templateVersion`, the raw overrides) so restoring a revision
writes back exactly what was stored. When a design is present, `BrandView.theme`, `tokens[theme]` and `fontPairId` are
set from it, so the favicon mark, the social image and QR codes keep working unchanged.

### 4.3 Database

- `BrandConfig`: `templateId String?`, `design Json @default("{}")`, `customTemplateId String?`
- `Restaurant`: `mapUrl String @default("")`, `showPoweredBy Boolean @default(true)`; `RestaurantType` gains `ICE_CREAM`
- `DesignTemplate`: `id`, `restaurantId?`, `name`, `basePresetId`, `overrides Json`, `createdById?`, `version`,
  timestamps; classified restaurant-or-shared like `MediaAsset`

## 5. The renderer

`TemplateMenu` replaces `MenuApp` when the live snapshot has a design (and in the Studio preview). It composes parts by
the resolved layout; every part reads colours and sizes from CSS variables set on its root.

| Part | Kinds |
|---|---|
| Hero | `editorial`, `asymmetric`, `arch`, `chapters`, `spotlight`, `carousel`, `pedestal`, `collection`, `daily`, `occasion`, `flavorWall`, `catch`, `compact` |
| Navigation (sticky) | `underline`, `pills`, `chips`, `index`, `chapters`, `segmented`, `tiles`, `dock` |
| Card | `row`, `plate`, `photo`, `ingredient`, `compact`, `gallery`, `isolated`, `list`, `flavor`, `oversized`, `cake`, `drink` |
| Detail | `sheet`, `drawer`, `page`, `card`, `steps` |
| Options | `list`, `chips`, `tiles` |

Each preset also has a skin class (`tpl-{id}`) for ornaments, dividers and type treatments. Common to all: search,
dietary filters (only tags that exist in the data), sold-out states, favourites (in this browser), the language switch
(names, never flags), business information, the cart bar when ordering is on, Powered by Buzzify.

## 6. Scenes

A scene is the preset's background. All three modes share one poster.

- Static: a CSS and SVG composition, no motion. Always painted first, and the fallback for everything.
- Motion: the same composition animated with CSS (ambient drift), shifted by scroll progress (a CSS variable) and
  answering taps with a small, local reaction.
- 3D: a React Three Fiber scene with real geometry, loaded only for the selected preset, only when the device qualifies
  (WebGL, no data saver, enough memory and cores), after the menu is interactive. Ambient movement, a tap reaction at
  the tapped point, scroll progress as a pure input (both directions), pointer parallax on fine pointers. Pixel ratio
  at most 1.5 on phones. Paused while the page is hidden or a product sheet covers it. WebGL failure, a lost context or
  a thrown error drops to motion, then static.

Background, tap and scroll can each be turned off, and intensity and speed adjusted, per business. Reduced motion
always gives static. Taps on buttons, links and fields never reach the scene; the scene layer never takes pointer
events or scroll. No reaction fires when a product is added.

## 7. Studio

A new Design tab (permission `brand.edit`): the gallery of Classic and the 30 presets with thumbnails, business type
and style filters, motion and 3D badges; a live preview of the business's own draft in phone, tablet and desktop frames;
Apply, Duplicate, Customize, Reset and Save as custom. Customizing updates the preview immediately (the preview frame
listens for messages from the Studio) and saves to the draft. The Brand tab keeps logos, favicon and name; with a
template applied its colour, type and motion controls give way to a link to the Design tab.

## 8. Not in stage 1

Uploaded motion and 3D assets, scoop-to-flavour rules, weight pricing, the cake inquiry form, order submission, table
sessions, analytics dashboards. The asset fields of a scene are reserved in its settings but not used.
